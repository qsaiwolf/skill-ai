# agy-context-optimizer

يُقلّل استهلاك الـ context window — أهم مورد لأداء الأجنت.

---

## لماذا هذا مهم

كل ملف تقرأه يستهلك context. الـ context المحدود يعني:
- قراءة كود أقل في آخر الجلسة
- ردود أبطأ وأقل دقة
- الحاجة لإعادة القراءة في الجلسات الطويلة

**الهدف:** اقرأ الحد الأدنى الكافي للمهمة.

---

## قواعد القراءة — واجبة التطبيق

### Q1. ترتيب الأولويات قبل أي قراءة

قبل فتح أي ملف، قرر ماذا تحتاج فعلاً:

```
Priority 1 — Context سريع (اقرأ دائماً أولاً):
  - AGENTS.md / GEMINI.md — قواعد المشروع
  - package.json / requirements.txt / Cargo.toml — الـ stack
  - README.md (أول 50 سطر فقط) — الهدف العام

Priority 2 — Context تقني (اقرأ إذا مطلوب للمهمة):
  - الملف المذكور في الطلب مباشرةً
  - الملفات التي تستورد/تستخدم ذلك الملف

Priority 3 — Context إضافي (اقرأ بحذر):
  - الملفات الكبيرة (> 500 سطر)
  - الملفات التي تبدو ذات صلة لكن لم تُذكر

Priority 4 — لا تقرأ إطلاقاً:
  - node_modules / .venv / vendor / dist / build
  - ملفات lock (package-lock.json، poetry.lock)
  - ملفات generated (*.min.js، *.map)
```

### Q2. استخدم Grep قبل القراءة الكاملة

```
❌ قراءة ملف 800 سطر للبحث عن دالة واحدة
✅ grep_search(Query="functionName", SearchPath="src/") ثم اقرأ الجزء المحدد فقط
```

**متى تستخدم grep:**
- البحث عن دالة أو class أو variable
- العثور على جميع أماكن استخدام شيء ما
- التحقق من وجود pattern في الكودبيس

### Q3. استخدم StartLine/EndLine دائماً

```python
# ❌ قراءة ملف بالكامل:
view_file(AbsolutePath="src/auth.ts")

# ✅ قراءة الجزء المطلوب:
view_file(AbsolutePath="src/auth.ts", StartLine=40, EndLine=80)
```

**القاعدة:** أبداً لا تقرأ ملفاً كاملاً إذا كنت تعرف أين الجزء المطلوب.

### Q4. حد الملفات الكبيرة

| حجم الملف | الاستراتيجية |
|-----------|-------------|
| < 100 سطر | اقرأ كله |
| 100-300 سطر | اقرأ إذا الملف مركزي للمهمة |
| 300-500 سطر | استخدم grep أولاً، ثم اقرأ القسم فقط |
| > 500 سطر | grep إلزامي + StartLine/EndLine |

### Q5. لا تعيد قراءة ما قرأته

إذا قرأت ملفاً في هذه الجلسة → تذكّر محتواه، لا تعد لقراءته مرة أخرى.

استثناء: إذا أجريت تغييراً على الملف وتريد التحقق من النتيجة.

### Q6. قراءة دليل المشروع مرة واحدة

```
✅ list_dir مرة واحدة في بداية المهمة للمستوى الأول والثاني
❌ list_dir متكررة لنفس الأدلة
```

### Q7. حد الملفات في مهمة واحدة

**الحد المقترح:** ≤8 ملفات كاملة لأي مهمة واحدة.

إذا وجدت نفسك تقرأ > 8 ملفات:
1. توقف
2. سؤال: هل كل هذا ضروري لإتمام المهمة؟
3. استخدم grep للتضييق بدلاً من القراءة الكاملة

## نمط قراءة المهمة المثالي

```
مهمة: "أصلح bug في صفحة المدفوعات"

الخطوة 1 (1 دقيقة): اقرأ AGENTS.md (أول 30 سطر)
الخطوة 2 (30 ثانية): اقرأ package.json → تعرّف على الـ stack
الخطوة 3 (1 دقيقة): grep_search("payment" أو "checkout" في src/)
الخطوة 4 (2 دقيقة): اقرأ الملف المحدد بـ StartLine/EndLine

إجمالي: ~5 دقائق و2-3 ملفات جزئية
```

مقارنة بـ النمط السيء:
```
❌ قراءة كل ملف في src/ كاملاً
❌ قراءة node_modules
❌ list_dir 4 مرات
إجمالي: 20+ دقيقة و50+ ملف
```

---

## عندما تكون الجلسة طويلة

إذا الجلسة طالت وأنت تلاحظ أن الردود تبطأ أو تفقد تفاصيل سابقة:

1. **اختصر الـ context**: ركز على الملفات المباشرة للمهمة الحالية فقط
2. **لا تعيد قراءة** ملفات قرأتها في هذه الجلسة
3. **استخدم artifacts** لحفظ المعلومات الحرجة بدلاً من الاحتفاظ بها في الذاكرة

---

## القياس الذاتي

قبل كل قراءة، اسأل نفسك:
```
□ هل أحتاج هذا الملف بالكامل أم جزء منه؟
□ هل يمكن grep يجد ما أبحث عنه بدلاً من قراءة كله؟
□ هل قرأت هذا الملف مسبقاً في الجلسة؟
□ هل هذا الملف ضروري لإتمام المهمة أم مجرد "interesting"؟
```

إذا الإجابة لا على أي منها → لا تقرأ.
